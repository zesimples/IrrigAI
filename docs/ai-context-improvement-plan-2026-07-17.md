## Merged verified findings (basis for the plan)

From your audit, confirmed: context copies only 8 fields of `inputs_snapshot` (`ai/context_builder.py:214-223`) while `services/recommendation_service.py:_make_inputs_snapshot` stores `etc_mm`, `rain_effective_mm`, `rain_skip_applies`, `swc_source`, `fc_calibration`, `dose_band/source/presentation`, `stress_projection`; `probe_summary.latest_readings` has no reading values (`context_builder.py:~638`); farm-wide weather query mixes plot-scoped rows (`context_builder.py:~524`); `RecommendationOutcome` invisible to AI and UI; evidence accepted unvalidated; structured output round-trips through bullet text (`render_structured` → `parseResultBullets`); "Recomendação da IA" hero is deterministic React (`sectors/[sectorId]/page.tsx` `buildAiLede`); `ChatPanel.tsx:167` hardcodes "Powered by GPT-4o" (default model is `gpt-4o-mini`); `tools.py:_get_sector_status` omits `recommendation_id` though `propose_accept/reject/override` require it; AI analyses persist only in `localStorage` (`SectorAnalysis.tsx:~270`); no LLM endpoint rate limits.

From the second audit, additional: `probe_signal.py` grades moisture against **plot** FC/WP (`~47-52`, `_moisture_level`) instead of `pipeline.resolve_sector_soil_bounds` — the "humidade crítica" labels that feed the probe guard use the wrong envelope on calibrated sectors; post-irrigation response uses only manual `IrrigationEvent` (`probe_signal.py:~97`) so unlogged farms always get `resposta_rega: null`; `build_farm_context` builds sectors serially (77× on Innoliva) and `to_json` uses `indent=2` (token bloat); chat `_seed_scope_context` builds the full farm context to emit 3 fields; `assistant._complete_structured` swallows all exceptions into canned confidence-0.3 advice (a dead API key looks like low confidence); the AI layer has **zero references** to `RecommendationOutcome`, `IrrigationFingerprint`, `ProbeCalibration(Run)`, `StressProjector`, GDD; CI is mock-only so prompt regressions ship undetected (this happened: the PT structured-output contract regression); orphaned endpoints beyond outcomes: change-analysis, alert-explain, calibration run history+apply (candidates from the candidate-only scheduler accumulate with no UI), ingestion diagnostics.

Staging changes vs your proposals: (a) evidence-ID registry is the agreed end state, but stage 1 is server-side **validation** of `evidence.source` paths (cheap), with the ID registry done later together with direct structured rendering, since both change the same response contract; (b) `SectorAIContextV2` must be **seeded from `Recommendation.inputs_snapshot` and the shared resolvers** (`resolve_sector_soil_bounds`, `build_weather_context`) rather than re-deriving from raw tables — the current drift exists because `context_builder` re-derives what the engine already computed.

## Phased plan

### P0 — Consistency & trust fixes (IMPLEMENT NOW, each independently shippable)

1. **Plot-scoped weather in AI context.** `get_weather_summary` (and anything feeding sector AI weather) must resolve weather like the engine: sector → plot-scoped rows, falling back to farm-level (`plot_id IS NULL`), via `engine/pipeline.build_weather_context` or an equivalent shared helper. Acceptance: for a sector on a plot with plot-scoped weather, AI context contains only that plot's observations; farm-level farms unchanged; test covers both branches.
2. **Resolved soil bounds everywhere in the AI layer.** `context_builder`'s `soil` block and `probe_signal`'s FC/WP (moisture grading + `flatline_near_fc`) must come from `resolve_sector_soil_bounds`, and the context must include provenance `{source, stale, computed_at}`. Acceptance: on a sector with probe calibration, AI context FC equals the engine's effective FC, not `plot.field_capacity`; test asserts the qualitative moisture label changes accordingly.
3. **Full `inputs_snapshot` passthrough.** Extend `SectorAssistantContext` (and the structured context's `water_balance` block) with `etc_mm`, `rain_effective_mm`, `rain_skip_applies`, `swc_source`, `fc_calibration`, `dose_band`, `dose_source`, `dose_presentation`, `stress_projection`, confidence penalties. Update `RECOMMENDATION_EXPLANATION_PT` only if needed to reference the new fields; do not loosen its rules.
4. **Reading values in `latest_readings` + one canonical probe representation.** Add the latest VWC (calibrated preferred) per depth to `probe_summary.latest_readings`; make the card path (`probe_live`) and structured path describe probe state identically (extract a shared builder).
5. **`get_sector_status` returns `recommendation_id`, `generated_at`, `is_accepted`;** validate that a supplied `sector_id` belongs to the scoped `farm_id` in chat tools. Acceptance: mock-client chat test can accept a recommendation using only tool outputs.
6. **Probe response uses detected events.** `probe_signal` post-irrigation analysis considers `DetectedWaterEvent` (confirmed/active irrigation kind) and flowmeter-detected events when no manual `IrrigationEvent` exists; include event source in the stats dict.
7. **Label honesty (frontend copy only).** "Recomendação da IA" → "Recomendação IrrigAI"; LLM cards labelled "Explicação com IA"; `ChatPanel` "Powered by GPT-4o" → "Assistente IrrigAI" (no model name); "Calibração AI" button → "Calibração inteligente" (keep internal keys/routes unchanged).

Plus, pulled forward from P4 because every later phase edits prompts/contexts:

17. **Golden-set eval harness.** `backend/tests/ai_eval/` (excluded from default CI run): ~20 recorded real context JSONs; assertions per surface: response fields in pt-PT, every `evidence.source` resolves to a real path in the provided context, probe guard holds when engine action ∈ {skip, defer}, no raw VWC decimals in probe advice, farm summary lists "Rega urgente" only for `action == "irrigate"`. Runnable on demand with `LLM_PROVIDER=openai` (skip cleanly when no key). Document how to add cases.

### P1 — Canonical `SectorAIContextV2`
Ten blocks (scope, engine_decision, water_balance, probe_state, weather, irrigation_execution, outcomes, crop_state, calibration, alerts_and_limitations), each with `observed_at`/source/units; seeded from `inputs_snapshot` + shared resolvers; full for chat/diagnosis/change-analysis, compact digest for cards. Brings in `RecommendationOutcome` (last ~10), `IrrigationFingerprint` (habitual dose), calibration + pending candidates, GDD progress, stress projection, flowmeter execution.

### P2 — Verifiable evidence + honest rendering
Evidence-ID registry (backend-generated IDs, model cites IDs, backend resolves values) together with direct React rendering of the structured object (retire `parseResultBullets`).

### P3 — Memory & chat
Field-observations table (sector, author, type, structured value + text, expiry, verified) feeding context; server-side chat persistence; new read tools (`get_outcomes`, `get_calibration_status`, `get_recommendation_history`, `get_flowmeter_summary`, `get_stress_projection`); streaming.

### P4 — Cost, robustness, evals (remainder)
Rate limits on `/chat/*` + input length caps + timeouts + daily ceiling + cached farm summary keyed by context digest; farm-context aggregate query (kill 77× serial builds) and drop `indent=2`; `_complete_structured` stops swallowing exceptions (log + metric + `degraded: true` surfaced in UI); thumbs feedback capture.

### P5 — New surfaces
"Eficácia da rega" (rec → measured dose → probe response by depth → outcome residuals; LLM explains patterns, never adjusts coefficients); wire orphaned endpoints: change-analysis card, alert explanation, outcomes view, calibration run history + apply UI (treat as bug), ingestion diagnostics.

### P6 — Model routing (last)
Only after P0–P4, evaluate tiered models per surface using the eval harness as the yardstick.
